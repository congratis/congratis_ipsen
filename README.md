# Congratis

Интерактивная новогодняя ёлка с 20 шарами и персональными одноразовыми приглашениями.

## Stack

- Rust, Axum, Tokio
- RethinkDB 2.4.x через закреплённый Rust-драйвер `reql = 0.11.2`
- HTML/CSS/JavaScript
- Docker Compose
- Nginx/SSE — следующие этапы миграции

## Локальный запуск RethinkDB-ветки

1. Скопируйте `.env.example` в `.env`.
2. Установите длинный случайный `RETHINKDB_PASSWORD`.
3. Запустите приложение и базу: `docker compose -f docker-compose.rethinkdb.yml up -d --build`.
4. Создайте приглашения один раз: `docker compose -f docker-compose.rethinkdb.yml exec app generate-tokens 20`.
5. Раздайте каждому сотруднику только его персональную ссылку из вывода команды.

Приложение будет доступно локально на `http://localhost:8080`.

## Архитектура текущей ветки

- Одна запись `ornaments` на шар; `id` равен номеру шара и защищает от повторного назначения номера.
- В БД хранится SHA-256 токена, исходный токен выводится только в персональной ссылке.
- Погашение приглашения — условный ReQL update одного документа; проверка `used` и запись поздравления выполняются атомарно.
- Конкурентный интеграционный тест проверяет, что из двух одновременных отправок проходит ровно одна.

## Важное ограничение

Ветка `feat/rethinkdb-sse` — поэтапная миграция, не готовая production-конфигурация. Текущий этап переносит модель данных и обработчики на RethinkDB. Changefeed/SSE, Nginx в Docker и итоговый production deployment на Ubuntu 24.04 LTS будут следующими этапами. Не разворачивайте эту ветку в production до завершения этих этапов и зелёных интеграционных проверок.

Не коммитьте `.env` или файл с приглашениями. Подробный план — [ADR RethinkDB](docs/ADR-RETHINKDB-REALTIME.md).
